# Title Select

**ROM organizer**  
**Well kept. Ready to play.**

Identity v1.1 · 29 October 2026

## Position

Title Select puts the choice of game titles and releases at the heart of the collection. Arcade, console, handheld and other game systems are all in scope, including MAME collections. It preserves meticulously curated source sets across those systems and derives selected libraries for a device, purpose or preference.

The name connects the game-menu language of selection with the practical work of organizing titles. Use **Title Select** in prose and the supplied **TITLE SELECT** artwork in the logo. Keep the two words separate. The short descriptor is **ROM organizer**; supporting copy can use **ROM curation utility** when the context needs more detail.

### Three principles

1. **Keep.** Preserve source files, variants, provenance and integrity records.
2. **Select.** Choose releases through explicit region, language and revision rules, with an inspectable reason for every decision.
3. **Play.** Derive a useful library with the files and dependencies each selected release needs.

Personality: confident in presentation, meticulous in operation, enthusiastic about games and respectful of the collection.

## Visual direction

The identity draws on arcade marquee confidence, console packaging hierarchy and handheld menu economy. The late-1980s and 1990s references inform the energy, while modern typography makes the product useful today. Cobalt block lettering, warm paper and carbon frames support a three-color selector: cobalt outer bars, a red selected bar and a yellow cursor. The shared idea is choosing a game, across systems.

The name now gives the graphics a specific organizing idea: the menu. Numbered rows, a triangular cursor, selected-row brackets and a visible chosen state connect brand expression with the product's purpose.

Campaigns can be energetic. Working views should be calm and inspectable, with the same palette and sharp geometry.

### Pixel lettering and pixel art

Pixel accents are optional, never the default font system. The main wordmark stays smooth, bold and forward-slanted. No replica of a specific NES or SNES game font is prescribed.

- Use one short pixel label, such as **READY** or **SELECT**, in a campaign or celebratory panel.
- Keep pixel details to roughly a tenth of the visual emphasis; this is a design budget, not a measured requirement.
- Use coherent grid lettering or tiny original motifs. Scale on whole pixels and inspect at the intended display size.
- Keep game titles, body copy, controls, filenames, hashes and dense metadata in the modern type families.
- Avoid borrowed sprites and platform-specific controller silhouettes. Keep the symbolism broad enough for arcade, console, handheld and other systems.

The PDF includes an original 5 × 7 **READY** lettering specimen as campaign artwork, not a bundled or product-ready font. No new pixel font dependency is required.

## Graphic language

Use one dominant motif per composition:

1. **Packaging grid.** A flat square grid in an edge, spine or empty field. Keep grids away from body text and data.
2. **Selector rhythm.** Three numbered rows, one highlighted, with a triangular cursor. Brand expressions can read **01 Keep / 02 Select / 03 Play**.
3. **Solid offset.** A 4–6 px hard offset behind a campaign panel, with a crisp keyline.

Use rectangular frames and compact technical labels. The identity should feel deliberate and organized. Arcade contributes marquee hierarchy, consoles contribute packaging structure, and handhelds contribute compact menu rhythm. Use these as design cues rather than literal hardware illustrations. Avoid console-specific hardware silhouettes, recreated platform logos, signature seals, misty neon, glitch effects and perspective-grid horizons.

### Optional gradient treatment

The primary identity uses flat colors. For an occasional splash screen or campaign, a restrained Cobalt `#1847D1` to Campaign violet `#7043D7` gradient may appear across **SELECT** only. Keep **TITLE** and the emblem solid cobalt in that variation. Do not combine a gradient wordmark with the multicolor emblem, add glow, or apply gradients to working controls. A dedicated gradient logo asset is not included in this kit.

## Working interface

- Use a 4 px spacing grid, with common gaps of 8, 16 and 24 px.
- Use 2 px control corners, 1 px dividers and flat controls.
- Use 40 px rows by default, with comfortable targeting and keyboard navigation.
- Show a visible focus indicator, clear selection and inspectable details.
- Use 120–160 ms transitions and respect reduced motion.
- Lead with integrity, unresolved review items and the chosen play library.
- Keep collection-coverage metrics secondary to useful decisions.
- Keep Source sets, Play libraries, Profiles and Reports easy to distinguish.

## Product vocabulary

| Term | Meaning |
|---|---|
| Source set | Preserved files, variants, provenance and verification records |
| Play library | Derived selections for a device, purpose or preference |
| Profile | Region, language, revision, compatibility and inclusion rules |
| Build library | Create output from the selected source files and profile |
| 1G1R | One game, one selected release; keep every file that release needs |
| Verified | Matched a named reference using a stated check |
| Selected | Chosen by a profile |
| Unmatched | No reference match; an unresolved result rather than proof of damage |
| Needs review | A check or decision remains unresolved |
| Ready for export | Required output files are present; separate from launch testing |

Library building should be reproducible. Preserve source variants and record selection reasons. Multi-disc releases, arcade sets and other dependent formats must retain required discs, tracks, BIOS and dependencies as the system needs them. Unselected files can still have preservation value. Verification alone does not establish playability.

For MAME, the selected game may depend on parent data, BIOS, device sets or CHDs. Selection must preserve the required dependency closure for the chosen output arrangement. Count selected games separately from their files and supporting sets. Do not imply that 1G1R literally means one ZIP or one physical file, or that every clone is an unwanted duplicate.

Technical reference: [MAME documentation: About ROMs and Sets](https://docs.mamedev.org/usingmame/aboutromsets.html), consulted 29 October 2026.

## Voice

Use enthusiasm in campaigns and exactness in workflows. Name the action, explain the result and make uncertainty visible.

| Situation | Example |
|---|---|
| Campaign | Great collections. Ready to play. |
| Empty state | Start with a source set. Choose a folder to scan and verify. |
| Review | 3 files need review. No reference match found. Inspect the details before selecting. |
| Selection | English preferred. Revision 2 selected. Other versions remain in the source set. |
| Completion | Your library is built. 620 games ready for export. Source files unchanged. |

Prefer **organizer**, **utility**, **collection**, **source set**, **verify**, **select**, **build** and **play library**. Avoid collection-size bragging and completion pressure. Let a small, well-chosen library feel complete.
